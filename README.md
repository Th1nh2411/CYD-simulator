# CYD 캐릭터 + 알림 펌웨어

전체 구성은 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), 작업 이어받기는 [docs/HANDOFF.md](docs/HANDOFF.md)를 보세요.
Mac에서 실행하는 명령(시뮬레이터, Capri brain, AI Buddy): [docs/RUN-LOCAL.md](docs/RUN-LOCAL.md).

## 캐릭터 버전

| 버전 | git 태그 | 바로 올리기 | 내용 |
|---|---|---|---|
| **슬라임 (slime)** | `slime` | `releases/slime/cyd2usb-slime.bin` | 유체 물방울 캐릭터, 스~윽 텅 이동, 꾸미기와 프리셋 ([releases/slime](releases/slime/README.md)) |
| **픽셀 몬스터 (monster)** | (아직 없음) | – | 포켓몬 같은 2D 픽셀 몬스터. 스타팅 3종(불꽃 엠버, 풀 잎새, 물 방울). 필드를 돌아다니다가 알림은 아래 대화창, 승인 요청은 배틀 화면에서 기술로 응답 |
| **Capri (capri)** | (아직 없음) | – | Cyberpunk: Edgerunners의 Capri(비공식 팬 캐릭터, 비상업 전용: [art/capri/CREDITS.md](art/capri/CREDITS.md)). 글리치·순간이동, cyberpunk 패널에 그녀의 말투로 알림, 컷인, 소리. PC의 brain(`tools/capri/capri_brain.py`, Gemini API)과 답 버튼으로 대화, 리마인더, Claude Code 훅(권한 요청을 기기에서 허용/거절) |

지금 펌웨어에는 슬라임, 픽셀 몬스터, 애니(미연시 히로인, `heroine`), Capri(`capri`, CYD 빌드에는 없음)가 함께 들어 있고, 설정 페이지 맨 위나 시리얼 `char <이름>`으로 바로 바꿉니다. **CYD는 기본 빌드에서 애니를 뺍니다**(그림이 약 440 KB라 OTA용 두 칸 파티션의 한 칸이 거의 참). 애니가 필요하면 `python -m platformio run -e cyd2usb_anime -t upload`로 올립니다. 플래시가 16 MB인 보드는 늘 들어 있습니다. 알림과 승인 요청은 **한글**도 표시되고(KS X 1001 2,350자), 화면 오른쪽 위에 **시계**가 있습니다.

2D 캐릭터가 화면에 살고, Wi-Fi로 서버에서 받은 알림을 띄우는 펌웨어입니다.
보드나 SoC가 바뀌어도 **코드를 고치지 않고 파일을 추가하거나 설정만 바꿔서** 테스트할 수 있게 설계했습니다.

## 구조

```
src/
  app/                 순수 C++ (플랫폼 헤더 없음) — 보드가 바뀌어도 수정하지 않음
    core/              잠금 없는 큐 / 트리플 버퍼 (스레드 간 통신)
    engine/            기분 + 카드 큐(알림·승인 요청). 픽셀을 모름. 응답 결과(Outcome)를 내보냄
    gfx/               레이어 합성기(바뀐 영역만 렌더), Canvas, 폰트(영문 5×7, 한글 갈무리11), 픽셀아트
    ui/                엔진 상태 → 레이어와 레이아웃. 터치 → 의미 이벤트. 캐릭터 인터페이스와 등록(characters)
      blob/            슬라임: 연체 물리(FluidBody), 움직임·표정(BlobAnimator),
                       렌더러(BlobLayer), 파라메트릭 눈(eye), 설정(CharacterConfig + JSON)
      monster/         픽셀 몬스터: 스타팅 3종, 필드·대화창·배틀, 설정(MonsterConfig + JSON)
      heroine/         애니(미연시 히로인): 초상화·방·대화창, 설정
  hal/                 인터페이스: Display, Touch, Backlight, Board
  drivers/
    panels/            화면 컨트롤러 초기화 테이블 (ILI9341, ST7789 …)
    esp32/             ESP32 전용 드라이버 (DMA SPI 디스플레이, LEDC 백라이트)
    common/            Arduino 공통 드라이버 (XPT2046 터치)
    web/               시뮬레이터용 (캔버스 디스플레이, 마우스 터치)
  platform/esp32/      태스크 배치, Wi-Fi AP, 웹 서버(설정 페이지 + API), 설정 저장(NVS), 시리얼
  platform/common/     설정 API의 JSON, 테스트 카드 (웹 서버, 시리얼, 시뮬레이터가 공유)
  platform/web/        웹 시뮬레이터 런타임 + 페이지
  boards/cyd2usb/      이 보드의 핀 + 드라이버 선택
  boards/web/          시뮬레이터 보드 (CYD2USB와 같은 320×240)
  tools/hw_test/       이전 TFT_eSPI 하드웨어 테스트 펌웨어
art/                  캐릭터 그림 세트 (아래 "캐릭터 그림")
tools/                PC 도구: 그림 변환(sprites, rig), 시뮬레이터(web), 시리얼, MQTT, 폰트
```

`app/`이 쓰는 외부 라이브러리는 ArduinoJson 하나입니다(헤더만 있고 Arduino에 의존하지 않음).

데이터 흐름: `터치 → ui(TouchGesture → handleTap) → 엔진 이벤트 큐 → engine.tick → WorldState 스냅샷 → ui.update → 레이어 → 합성기 → DMA`

### 픽셀 몬스터

| 상태 | 화면 |
|---|---|
| 평상시 | 위에서 본 풀밭을 돌아다님. 가끔 두리번거리고, 30초 동안 일이 없으면 잠듦. 몬스터를 탭하면 폴짝, 풀밭을 탭하면 그 자리로 걸어감 |
| 알림 | 머리 위에 "!" → 아래 대화창에 제목과 내용이 한 글자씩 나옴. 대화창을 탭하거나 6초가 지나면 닫힘 |
| 승인 요청 | 번쩍 → 배틀 화면. "야생의 ○○이(가) 나타났다!" → 선택지가 기술 메뉴로 나옴 → 고르면 기술 연출("엠버의 승인!") → 필드로 돌아옴 |

- 스타팅: 불꽃 **엠버**(꼬리 불꽃 도마뱀), 풀 **잎새**(등에 잎이 난 네발 새싹), 물 **방울**(거북). 그림은 오리지널이고 셋 다 목도리를 둘렀습니다. 기술 연출도 종마다 다릅니다(불꽃, 잎사귀, 물방울).
- 설정: 스타팅, 이름(한글 8자), 색 6개, 픽셀 크기, 걷는 속도, 글자 속도, 잠들기까지 시간, 레벨. 프리셋 ember, leaf, bubble, frost, shiny, night.

### 슬라임 화면 배치

| 상태 | 캐릭터 | 카드 |
|---|---|---|
| 평상시 | 화면 중앙에 떠 있음 | 없음 |
| 알림 | 위로 빠르게 이동, 시선은 카드 | 아래에서 올라옴. 탭하거나 6초가 지나면 닫힘 |
| 승인 요청 (가로 화면) | 왼쪽으로 이동, 시선은 버튼 | 오른쪽에서 들어옴. 버튼 2~3개. 60초 동안 응답이 없으면 만료 |
| 승인 요청 (세로 화면) | 위로 이동 | 아래에서 올라옴 |

이동은 **스~~윽 텅!** 방식입니다. 평소의 물성(숨쉬기, 통통 튐, 터치 물결)은 그대로이고, 위나 옆으로 **이동할 때만** 모양이 바뀝니다.
- 빠르게 미끄러집니다(기본 260 ms). 출발은 부드럽고 점점 빨라집니다.
- 꼬리 끝은 이동 경로에 매우 무른 스프링으로 매달려 있습니다. 그래서 머리가 앞서 달려 나가면 뒤가 따라오지 못하고 **동그란 머리 + 길고 뾰족한 꼬리**(몸 반지름의 최대 3배)로 늘어납니다. 부피가 보존되어 꼬리가 길어지면 머리는 작아집니다.
- 멈추는 순간 진행 방향으로 납작하게 눌리고("텅"), 스프링이 단단해지면서 꼬리가 빠르게 달려와 합쳐지며 출렁입니다.
- 웹에서 조절하는 값: `glideMs`(이동 시간), `thud`(0 부드럽게 ~ 1 세게), `drop`(꼬리 늘어남 0~3)
- `splash`(꼬리에서 물방울이 떨어짐)는 실험 기능이라 기본으로 꺼져 있습니다.

### 몸(머리) 형태 · 눈썹 · 프리셋

- **몸 형태** `bodyShape`: round(동그라미), egg(달걀), mochi(찹쌀떡), drop(물방울), squircle(둥근 사각), cat(고양이), bean(강낭콩)
  - 가로세로 비율은 `aspect`로 따로 조절합니다.
  - 형태가 달라도 면적은 같게 맞춥니다.
  - 형태를 바꾸면 몸이 새 모양으로 흘러가듯 바뀝니다.
- **눈썹** `brows.style`: none, line(일자), arch(아치), thick(굵은 일자), dot(점 눈썹)
  - 색, 두께, 길이, 눈과의 간격을 조절합니다.
  - 높이와 각도는 표정마다 정해집니다(`browRaise`, `browAngle`). 화남은 안쪽이 내려가고, 슬픔은 안쪽이 올라가고, 놀람은 위로 올라갑니다.
- **안광:** 시선과 함께 움직이고, 위 눈꺼풀이 내려오면 보이는 눈 영역 안으로 같이 내려옵니다.
- **프리셋:** aqua(물방울), sprout(새싹이), kitty(고양이), robo(로봇), angel(천사), imp(꼬마 악마), royal(왕관), party(파티), mochi(찹쌀떡)
  - 기본값 위에 덮어쓰는 JSON이고, 웹이나 저장 설정과 같은 형식입니다.
  - 적용한 다음 수정하고 저장할 수 있습니다.

### 꾸미기 (장식)

| 부위 | 종류 | 비고 |
|---|---|---|
| 머리 `head` | antenna, sprout, bow, ears, horns, crown | 몸 표면에 붙어서 같이 출렁이고, 관성으로 흔들림 |
| 등 `back` | wings, fin, spikes | 몸 뒤에 그려서 반투명한 몸 너머로 비침. 날개는 파닥이고, 이동할 때 빨라짐 |
| 왼손·오른손 `left`·`right` | arm, heart, star, flag, balloon | 팔은 몸 뒤에서 나옴. 기쁠 때 손을 흔듦 |

부위마다 종류, 색 2개, 크기, 위치(외곽선을 따라 각도 −90~90°)를 정합니다. 모두 도형(거리 함수)으로 그려서 해상도와 상관없이 매끄럽습니다.

눈의 안광(반짝임)은 시선 방향으로 눈 안에서 움직입니다. 이동 폭은 `shineTravel`로 조절합니다.

## 캐릭터 그림 (`art/`)

그림은 코드 밖 `art/<캐릭터>/` 폴더에 세트로 둡니다. 변환 결과 표는 `src/`에 생성되어 저장소에 들어갑니다.

- **픽셀 몬스터 `art/monster/`:** PNG 스프라이트 시트와 `sprites.json`. 공통 시트(모든 몬스터가 같이 씀: 상대 `foe.png`, 타일 `tiles.png`, 말풍선 `emotes.png`)와, 몬스터마다 같은 배치의 시트 두 장(필드 `<id>.png`: 16×16 격자, 아래·위·옆·들림 × 서기·걷기, 잠 / 배틀 뒷모습 `<id>_back.png`, 32×32)과 정보(이름표, 기본 이름, 기본 색, 기술 모양, 특징 이름, 프리셋). **몬스터 추가는 그림과 정보만으로 됩니다**: 리그 스튜디오에서 기존 몬스터를 복사해 추가하고 시트를 새로 그려 올리면, 다음 빌드부터 설정의 스타팅 고르기에 나옵니다(펌웨어 코드는 그대로). 도트 편집기로 PNG를 고치고 빌드하면 됩니다: 빌드(기기, 시뮬레이터) 전에 `tools/sprites/sprites.py`가 바뀐 시트를 `monster_art.h`로 바꿉니다. 시트의 색은 팔레트 자리를 고르는 열쇠이고 실제 색은 설정(몸·배·목도리 색)에서 계산합니다. `sprites.json`에 없는 색이나 격자와 안 맞는 크기는 위치와 함께 빌드 오류가 납니다. 시트를 정수배로 키워 그려도 됩니다.
- **애니 `art/heroine/`:** 그림(원본 `base_source.webp`, 표정 편집본 `src/`, 방 `room.svg`)과 리깅(`rig.json`: 얼굴 영역, 표정 목록, 고개 기울임 피벗·목·머리카락 행·단계, 가슴 행, 방 시간대 색)이 한 세트입니다. 변환기는 빌드와 따로 돌립니다(Python + OpenCV, 수십 초~수 분). 누끼 → 표정 맞춤 → 자세 굽기 → 방 중 입력이 바뀐 단계만 다시 합니다(피벗만 옮기면 자세만, 약 20초).

웹에서 하려면 리그 스튜디오를 띄웁니다. 단계를 따라가면 됩니다: 1 원본 그림(어떤 그림을 넣을지 예시와 체크리스트, 이미지 모델에 할 부탁 문장) → 2 누끼 → 3 고개(그림 위에서 피벗과 목·머리카락·가슴 선을 끌고, 기기 크기로 고개를 흔드는 미리보기) → 4 얼굴(눈·눈썹·입 자리) → 5 표정(펌웨어가 쓰는 13개를 카드마다 설명·예시 얼굴·부탁 문장과 함께 한 장씩 올림) → 6 변환. 몬스터 같은 도트 스프라이트 세트도 같은 화면에서 시트를 칸 이름·팔레트와 함께 보고, 고친 PNG를 올리면 바로 검사해 적용합니다(안 맞으면 되돌림).

```bash
python tools/rig/studio.py
```

(http://localhost:8770) 명령줄로는:

```bash
python tools/rig/convert.py art/heroine
```

## 웹 화면 시뮬레이터 (기기 없이)

움직임 센서는 키로 흉내 냅니다: 방향키를 누르는 동안 그쪽으로 기울고, `S`는 흔들기(카드가 없으면 테스트 카드가 뜸).

```bash
python tools/web/sim.py
```

- 브라우저에 `http://localhost:8766`가 열립니다. 왼쪽은 화면이고 마우스가 터치입니다. 오른쪽은 기기와 같은 설정 페이지입니다.
- 펌웨어와 **같은 C++ 소스**(`src/app/`)를 WebAssembly로 빌드한 것이라 그려지는 화면이 같습니다. 성능(CPU, fps, 힙)과 실제 패널 색은 기기에서 확인하세요.
- 소스를 저장하면 자동으로 다시 빌드하고 페이지를 새로 고칩니다. 컴파일 오류는 페이지 아래에 표시됩니다.
- 저장 버튼은 브라우저(localStorage)에 저장합니다.
- 필요한 것: [emsdk](https://emscripten.org/docs/getting_started/downloads.html)를 저장소 옆(`C:\Workspace\emsdk`)에 설치하거나 `--emsdk` 경로를 지정합니다. ArduinoJson은 PlatformIO가 받은 것을 씁니다.
- 빌드만 하려면 `python tools/web/sim.py --build`를 실행합니다. 결과물은 `build/web/`에 생깁니다.
- 같은 Wi-Fi의 폰이나 다른 PC에서 보려면 `python tools/web/sim.py --host 0.0.0.0`으로 띄우고 `http://<PC의 IP>:8766`을 엽니다. Windows 방화벽에서 python.exe의 들어오는 연결(개인 네트워크)을 허용해야 합니다.
- 시계는 브라우저 시간을 씁니다.

## 캐릭터 설정 (Blob Studio)

### PC에서 USB로 (Wi-Fi 연결 필요 없음)

```bash
python tools/studio/serial_studio.py COM3
```

- 브라우저에 `http://localhost:8765`가 열리고, 기기 안의 설정 페이지와 같은 화면이 나옵니다.
- 변경 사항은 USB 시리얼로 바로 기기에 반영됩니다. PC는 원래 인터넷에 연결된 채로 쓸 수 있습니다.
- 실행하는 동안 COM3를 잡고 있습니다. 펌웨어를 올리기 전에는 꼭 Ctrl+C로 끄세요.

### 폰이나 PC에서 기기 Wi-Fi로

1. 폰이나 PC로 Wi-Fi **`CYD-Blob-XXXX`**(비밀번호 `blob1234`)에 접속합니다. XXXX는 MAC 끝자리이고, 부팅할 때 화면 알림과 시리얼에 표시됩니다.
2. 브라우저에서 **http://192.168.4.1** 을 엽니다. 페이지를 열면 기기 시계가 폰 시간으로 맞춰집니다("시계 맞추기" 버튼도 있음).
3. 맨 위에서 캐릭터를 고르면 바로 바뀝니다. 아래 편집 칸은 고른 캐릭터 것입니다.
   - 슬라임: 색상, 크기, 투명도, 눈 세트(oval / robot / dot / pill), 표정별 눈 모양, 꾸미기(머리·등·양손), 움직임, 유체 물리(기본 / 말랑이 / 슬라임 프리셋)
   - 픽셀 몬스터: 스타팅, 이름, 색, 픽셀 크기, 속도
   - 바꾸면 재부팅 없이 바로 반영됩니다.
4. **저장**을 누르면 모든 캐릭터 설정과 선택이 NVS에 보관되어 전원을 껐다 켜도 유지됩니다. 시계는 전원이 꺼지면 다시 맞춰야 합니다.

API (기기 AP에 접속한 상태에서):

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/api/config` | 활성 캐릭터 설정. `{"character":"slime","slime":{...}}` |
| POST | `/api/config` | 일부만 보내도 병합됨. 예: `{"character":"monster"}`(전환), `{"slime":{"body":"#ff8844","eyeSet":"robot"}}`, `{"monster":{"name":"불꽃이"}}`. 슬라임 키만 최상위에 둔 예전 형식도 됨 |
| POST | `/api/save` / `/api/reset` | 전부 저장 / 활성 캐릭터를 기본값으로 (저장은 하지 않음) |
| POST | `/api/preset` | `{"name":"kitty"}` 활성 캐릭터의 프리셋 적용 (저장은 하지 않음) |
| POST | `/api/preview` | `{"expr":"angry"}` 표정을 2.5초 동안 보여줌 |
| POST | `/api/card` | `{"kind":"prompt","title":"배포 요청","body":"...","options":["승인","거절"],"ref":7}` (한글 가능). `"sticky":true`면 자동으로 닫히지 않고 탭(승인 요청은 응답)할 때까지 남음 |
| POST | `/api/time` | `{"epoch":1790000000,"offset":540}` 시계 맞추기 (offset은 UTC 기준 분) |
| GET/POST | `/api/net` | 집 Wi-Fi와 MQTT 설정·상태 (아래). 보내면 바로 저장되고 다시 연결함 |
| GET/POST | `/api/display` | `{"rotation":90,"mirror":false}` 화면 방향(시계 방향 0·90·180·270도)과 좌우 반전(프리즘용). 바꾸면 저장하고 기기가 다시 시작함 |

## 집 Wi-Fi와 MQTT (서버에서 알림·승인 요청 보내기)

기기가 집 Wi-Fi에 붙어 MQTT 브로커로 연결합니다. 기기 쪽에서 밖으로 연결하니 공유기 설정은 필요 없습니다. 기기 AP(`CYD-Blob-XXXX`)는 그대로 켜져 있습니다.

1. 설정 페이지의 **네트워크** 칸에서 "설정 열기"를 누르고 Wi-Fi 이름·비밀번호, 브로커 주소(IP나 이름), 필요하면 포트·TLS·사용자·비밀번호를 넣고 **적용**합니다. 바로 저장되고 연결합니다. 상태 줄에 집 Wi-Fi IP와 MQTT 연결 상태가 나옵니다. 비밀번호 칸은 비워 두면 저장된 값을 그대로 씁니다.
   - 시리얼로는 `net {"wifi":{"ssid":"집","pass":"..."},"mqtt":{"host":"192.168.0.10"}}`(Bash에서 보내야 큰따옴표가 살아 있음), 확인은 `net`.
   - 집 Wi-Fi에 붙은 뒤에는 상태 줄에 나오는 `http://<집 Wi-Fi IP>/`로도 설정 페이지가 열립니다.
2. 토픽(기본 `blob/<MAC 끝 4자리>`, 설정에서 바꿀 수 있음):

| 토픽 | 방향 | 내용 |
|---|---|---|
| `blob/3294/card` | 기기가 받음 | `/api/card`와 같은 JSON |
| `blob/3294/time` | 기기가 받음 | `/api/time`과 같은 JSON (시계 맞추기) |
| `blob/3294/outcome` | 기기가 보냄 | 승인 요청 응답 `{"ref":7,"option":0}`. `option` -1은 60초 동안 응답 없음 |
| `blob/3294/status` | 기기가 보냄 (retained) | `{"online":true,"name":"CYD-Blob-3294","board":"CYD2USB","ip":"..."}`, 기기가 끊기면 `{"online":false}` |
| `blob/3294/battery` | 기기가 보냄 (retained) | `{"mv":4082,"pct":87}` 배터리 전압(최근 5번 읽은 중앙값)과 추정 퍼센트. 5분마다, 배터리 핀이 있는 보드만 (JC3248W535) |
| `blob/3294/battery/get` | 기기가 받음 | 내용은 아무거나. 받으면 새로 읽어 바로 `battery`로 보냄 |

브로커가 없으면 PC에서 시험용 브로커를 띄울 수 있습니다(파이썬 표준 라이브러리만, 시험용):

```bash
python tools/mqtt/blob_mqtt.py broker
```

- 상호 TLS(mTLS)를 시험하려면 `python tools/mqtt/make_certs.py --host <PC의 IP>`로 시험용 CA와 인증서를 만들고(`tools/mqtt/certs/`, git 제외), 브로커를 `... broker --tls-port 8883 --tls-cert tools/mqtt/certs/server.pem --tls-key tools/mqtt/certs/server.key --client-ca tools/mqtt/certs/ca.pem`로 띄운 뒤, 기기에 `POST /api/tls/ca`, `/api/tls/cert`, `/api/tls/key`로 `ca.pem`, `<기기>.pem`, `<기기>.key`를 보내고 MQTT를 `"tls":true, "port":8883`으로 바꿉니다(ARCHITECTURE 11.2a).
- 처음 띄울 때 Windows 방화벽이 python 허용을 물으면 "개인 네트워크"를 허용해야 기기가 들어옵니다. 시작할 때 PC의 IP가 나오니 그걸 기기의 브로커 주소로 넣으세요.
- 다른 창에서 보내기 (기기가 하나만 켜져 있으면 토픽을 알아서 찾음, 아니면 `--topic blob/3294`):

```bash
python tools/mqtt/blob_mqtt.py notify "새 메시지|빌드가 끝났어요"
```

```bash
python tools/mqtt/blob_mqtt.py prompt "배포 요청|v1.2를 배포할까요?|승인|거절"
```

- `prompt`는 응답을 기다렸다가 `answered: 0 승인`처럼 출력합니다(종료 코드 0 = 응답, 2 = 시간 초과). `--sticky`는 탭할 때까지 남는 카드, `time`은 PC 시계 보내기, `watch`는 기기가 보내는 것 모두 보기.
- Mosquitto 같은 다른 브로커도 됩니다: `mosquitto_pub -t blob/3294/card -m '{"kind":"notification","title":"hi","body":"there"}'`.
- TLS는 공개 인증서를 쓰는 브로커(클라우드 브로커 등)만 됩니다. 자체 서명 인증서는 아직 안 됩니다.

눈 모양 수치(모두 몸 반지름 대비 비율): `w`, `h`, `square`(0 타원 ~ 1 둥근 사각형), `corner`, `tilt`, `lidTop`, `lidAngle`(+ 화남, − 슬픔), `lidBottom`, `arc`(^ 웃는 눈), `shine`.

## 명령

```bash
pio run -t upload
```

```bash
pio device monitor
```

시리얼 모니터 명령 (한글은 UTF-8로 보내면 됨):
- `n 제목|내용`: 알림
- `p 제목|내용|선택1|선택2[|선택3]`: 승인 요청. 응답하면 `prompt N answered: option K`가 출력됨
- `char slime|monster`: 캐릭터 바꾸기 (저장하지 않음)
- `preset <이름>`: 활성 캐릭터의 프리셋 적용 (예: `preset kitty`, `preset leaf`, 저장하지 않음)
- `time HH:MM`: 시계 맞추기
- `menu`(`touchcal`도 같음): 화면에 설정 메뉴(설정 페이지의 "터치 보정" 버튼, BOOT 1초 길게 누르기와 같음). 터치 있는 보드는 1. 터치 보정(누른 자리가 어긋날 때), 2. 롱 프레스 보정(톡 8번, 꾹 5번으로 길게 누르기 시간을 정함), 3. 드래그 보정(제자리 누름 10번으로 드래그 기준을 정함), 그리고 AP 모드(기기 자체 Wi-Fi와 설정 페이지를 켜고 끔)와 닫기 중 고릅니다. 보정 중 BOOT는 취소
- `ota [https://주소]`: 펌웨어를 인터넷으로 업데이트(주소가 없으면 상태). 받는 동안 MQTT가 멈추고, 새 펌웨어가 30초 돌지 않고 죽으면 이전 것으로 되돌아갑니다. 웹의 `POST /api/ota {"url":"https://..."}`로도 됩니다(MQTT로는 안 됩니다: 이미지 서명 검사가 아직 없음). 시험은 `tools/mqtt/serve_ota.py`(ARCHITECTURE 11.2a)
- `web [on|off]`: 설정 웹 서버 상태 보기 / 켜기 / 끄기. 램을 아끼려고 부팅 후 10분 뒤 마지막 요청에서 5분이 지나면 스스로 꺼집니다(집 Wi-Fi가 연결돼 있으면 AP도 같이 꺼짐). 메뉴의 AP 모드로도 다시 켭니다
- `shape <형태>`, `brows <스타일>`: 슬라임 몸 형태 / 눈썹 바꾸기
- `eyes oval|robot|dot|pill`: 눈 세트 바꾸기
- `acc head|back|left|right <종류>`: 장식 바꾸기 (예: `acc back wings`, `acc right balloon`, `acc head none`)
- `face normal|happy|surprised|sleepy|angry|sad`: 표정 미리보기
- `config` / `config {json}`: 설정 출력 / 병합
- `save` / `reset`: 저장 / 기본값으로
- `net` / `net {json}`: 집 Wi-Fi·MQTT 설정과 상태 출력 / 병합(바로 저장)
- `stress`, `bench`: 최악 부하 / 그리기 비용과 메모리
- `sleep`: 화면을 끄고 딥 슬립. RST 버튼이나 USB를 다시 꽂아야 깨어남
- `rotate 0|90|180|270`: 화면 방향(시계 방향, 90 = 세로). 저장하고 다시 시작함. 설정 페이지의 "화면 방향"과 같음
- `mirror on|off`: 화면 좌우 반전(프리즘으로 볼 때). 저장하고 다시 시작함
- `imu`: 움직임 센서 값 5초 출력(SpotPear 보드). 기울이면 슬라임이 내리막으로 미끄러지고, 흔들면 알림이 닫히고(카드가 없으면 BOOT처럼 다음 테스트 카드가 뜨고), 왼쪽/오른쪽으로 기울여 잠시 버티면 승인 요청에 첫/마지막 선택지로 답함

2초마다 fps, 렌더 시간, 코어별 CPU, 힙이 출력됩니다.

터치는 뗄 때 탭으로 처리합니다. 캐릭터를 0.5초 길게 누르면 탭 대신 표정이 기쁨 → 놀람 → 졸림 → 화남 → 슬픔 순으로 2.5초씩 바뀝니다(슬라임은 표정 대신 살짝 움찔하고, 그대로 끌면 들고 다닐 수 있습니다). 캐릭터를 잡아 끌 수 있습니다(애니는 제외). 슬라임은 그냥 끌면 몸은 제자리에 두고 잡은 곳과 그 둘레가 손가락을 따라 늘어나거나(반대쪽이 그만큼 가늘어짐) 안쪽으로 밀면 들어가고(옆이 부풂), 길게 누른 뒤 끌면 몸째 들고 다닐 수 있습니다(늘어나며 따라오고, 그동안은 놀란 표정). 픽셀 몬스터는 끌면 들려서 따라옵니다. 놓으면 원래대로 돌아갑니다.

BOOT 버튼을 눌렀다 뗄 때마다 영어 알림 → 영어 승인 요청 → 한글 알림 → 한글 승인 요청이 차례로 뜹니다. PC 없이도 시험할 수 있습니다. 버튼 없는 보드(SpotPear)는 카드가 없을 때 흔들면 같은 순서로 뜹니다. 1초 길게 누르면 설정 메뉴가 뜹니다(터치 보정 3종, AP 모드, 닫기). 메뉴에서는 BOOT를 짧게 누르면 다음 항목, 길게 누르면 선택이라 터치가 너무 어긋났거나 없는 보드에서도 쓸 수 있습니다.

화면 조작:
- 캐릭터 탭 → 슬라임은 누른 자리에서 물결이 퍼지고 통통 튐, 픽셀 몬스터는 폴짝 뜀
- 알림 카드(대화창) 탭 → 닫힘
- 승인 요청 버튼(기술) 탭 → 응답하고 닫힘

## 측정 성능 (CYD2USB 실측)

유체 캐릭터 기준입니다. 화면 왼쪽 위 HUD에 `fps cpu 코어0%/코어1% draw ms`가 1초마다 표시됩니다.

프레임률은 상황에 따라 바뀝니다(적응형). 이동, 통통 튐, 터치, 카드 슬라이드 중에는 60fps, 숨쉬기·파닥임 같은 대기 동작은 30fps입니다.

| 상황 | fps | 그리기 / 프레임 | CPU 코어1 |
|---|---|---|---|
| 대기, 새싹 장식 (기본) | 20~30 | 4.2 ms | 18~20% |
| 대기, 장식 4개 (날개·풍선·하트·안테나) | 약 28 | 7.3 ms | 27% |
| 이동 (스~윽 텅), 장식 4개 | 약 50 (1초 이내) | 7.4 ms | 최대 55% |
| 대기, imp 프리셋 (물방울 몸·굵은 눈썹·뿔·가시) | 약 28 | 6.9 ms | 25~27% |
| 꼬리 끌며 이동, imp 프리셋 | 약 58 (1초 이내) | 7.5 ms | 최대 61% |
| 최악: 매 프레임 전체 화면 | 31 | 4.1 ms | 22% |
| 엔진 1틱 | – | 7~12 µs | – |

Wi-Fi AP와 웹 서버를 켠 상태에서 여유 RAM은 약 165 KB입니다.

- 렌더 시간 대부분은 SPI 전송(40 MHz)입니다. 그리는 동안 DMA가 이전 스트립을 보냅니다.

| 텍스트 1배 (글자 영역 기준) | 7.4 Mpx/s | 32.6 |
| 스프라이트 1배 (32×32 여러 개) | 5.4 Mpx/s | 44.4 |
| **SPI 전송 (40 MHz)** | **2.5 Mpx/s** | – |

- 전체 화면 한 프레임: 그리기 1.27 ms + SPI 30.74 ms. SPI가 이론 대역폭(40 Mbit/s)을 100% 쓰고 있습니다.
- 프레임당 바꿀 수 있는 면적: 60fps에서 약 4만 px(화면의 54%), 30fps에서 전체 화면입니다.
- 메모리: 내부 힙 254 KB(Wi-Fi 켜면 202 KB), 최대 연속 블록 110 KB, 정적 RAM 51 KB입니다.
- 스택 사용량: UI 약 2 KB / 6 KB, 엔진 약 0.6 KB / 4 KB입니다.
- 플래시: 앱 792 KB / 1.92 MB 슬롯(Wi-Fi 라이브러리 약 460 KB 포함). 파일시스템 128 KB, OTA용 두 번째 슬롯 1.92 MB가 있습니다.

- **병목은 CPU가 아니라 SPI 대역폭입니다.** 최악 상황에서도 코어1의 90%가 쉬고 있습니다. DMA를 기다리는 동안은 CPU를 쓰지 않습니다.
- Wi-Fi는 RAM을 약 52 KB 쓰고, CPU 부하와 렌더에는 거의 영향이 없습니다.
- 다음 단계 예산: TLS(약 40~50 KB)를 더해도 RAM 약 150 KB가 남습니다.
- CPU 측정(`-DPERF_PROBE=1`)은 idle 태스크를 깨워두므로 개발용입니다. 절전 단계에서 끕니다.
